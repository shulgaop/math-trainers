# Математические тренажёры

Русскоязычный учебный сайт для 6 класса с памятками, короткими видеообъяснениями, пошаговыми разборами и интерактивными тренажёрами. Сейчас доступны пропорции, проценты и координатный луч. Сборка, база данных, PHP и серверная логика не нужны.

**Опубликованный сайт:** [https://shulgaop.github.io/math-trainers/](https://shulgaop.github.io/math-trainers/). Репозиторий: [github.com/shulgaop/math-trainers](https://github.com/shulgaop/math-trainers).

## Что внутри

```text
math-trainers/
├── .github/workflows/
│   └── deploy.yml         # CI/CD: проверка и автодеплой на GitHub Pages
├── site/                  # Только публичные файлы сайта
│   ├── index.html         # Пропорции: LearnHarness-маршрут, видео, задачи, тренажёр
│   ├── procenty.html      # Проценты: 6 SVG-схем, задачи № 46–65 и № 81–94
│   ├── luch.html          # Луч и отрезки: схемы алгоритма и длины, задача № 60
│   ├── .nojekyll          # Отключение ненужной Jekyll-обработки
│   └── videos/            # Три MP4-ролика и три JPG-обложки
├── tests/
│   └── validate_site.py   # Проверка HTML, ссылок, ресурсов и JavaScript
├── docs/
│   └── GRAPHS.md          # Графы архитектуры, публикации и учебных тем
├── .gitignore             # Исключение кэшей, логов и ZIP из Git
├── AGENTS.md              # Правила работы Kimi Code над проектом
├── CONTEXT.md             # Текущее состояние, структура и контрольные ответы
├── CHANGELOG.md           # Журнал всех итераций
├── DEPLOYMENT.md          # GitHub Pages: настройка, обновление, откат
└── README.md              # Эта инструкция
```

Весь HTML, CSS и JavaScript находится непосредственно в трёх HTML-файлах. Отдельных библиотек и сборщиков нет. В папке `videos` лежат три вертикальных ролика MP4 (720 × 1280, H.264/AAC) и их JPG-обложки; эти видео работают без внешнего видеохостинга. В начале главной страницы есть подборка русскоязычных видео на YouTube и альтернатива на RuTube; в разделе четырёх подходов — ссылки на Khan Academy, YouTube и Bilibili. Для внешних роликов нужны интернет и доступность соответствующей платформы. Шрифт Nunito загружается с Google Fonts; при недоступности сервиса используются системные шрифты.

На главной странице раздел «Мой маршрут» адаптирует учебный цикл LearnHarness: диагностика → маршрут → предсказание → объяснение → проверка → практика. Внешняя AI-модель и API-ключи не используются. Маршрут и завершённые узлы сохраняются только в `localStorage` текущего браузера; при размещении на обычном статическом хостинге ничего дополнительно настраивать не нужно. Для работы сохранения не отключайте данные сайта в браузере. Кнопка «Сбросить прогресс» удаляет сохранённый маршрут.

Во всех трёх тренажёрах кнопка «Мои ошибки» открывает неверно решённые задания. Сохраняются условие, последний неверный ответ и подсказка; в тренажёре луча сохраняется и исходная SVG-схема. Разбор раскрывается отдельно, а кнопка «Решить снова» возвращает то же задание. После верного повторного ответа оно удаляется из списка. Список ошибок и счёт живут только в памяти открытой страницы и после перезагрузки очищаются.

## Рекомендуемая публикация: GitHub Pages

Проект уже содержит CI/CD. После первичной настройки каждый `git push` в `main` проверяет сайт и автоматически публикует содержимое `site`; Pull Request только проверяется. Секреты и API-ключи не нужны.

1. Создайте пустой GitHub-репозиторий и отправьте в него все файлы проекта, включая скрытую папку `.github`.
2. В **Settings → Pages → Source** выберите **GitHub Actions**.
3. Дождитесь зелёных `validate` и `deploy` на вкладке **Actions**.
4. Откройте URL из результата `deploy`.

Подробные команды для **Windows PowerShell и WSL**, первый запуск, ежедневное обновление, откат, защита ветки и собственный домен — в **`DEPLOYMENT.md`**. Сохранение версии Kimi или успешная локальная проверка не считаются публикацией.

## Ручное размещение на обычном хостинге

Используйте этот вариант только если GitHub Pages не нужен.

1. Распакуйте архив.
2. Откройте папку `site`.
3. Загрузите **содержимое папки `site`** в корневую папку сайта на хостинге. Обычно она называется `public_html`, `www`, `htdocs` или `httpdocs`. Обязательно загрузите папку `videos` целиком, не только HTML-файлы.
4. Проверьте, что главный файл оказался по адресу вида `public_html/index.html`, а ролики — например, `public_html/videos/proporcii.mp4`, без лишней вложенной папки.
5. Откройте домен в браузере. Должна загрузиться страница «Пропорции на пальцах».
6. Проверьте остальные адреса:
   - `https://ваш-домен/procenty.html` — проценты;
   - `https://ваш-домен/luch.html` — координатный луч.
7. Если на хостинге ещё нет HTTPS, включите бесплатный SSL-сертификат в панели хостинга.

**Если на домене уже есть другой сайт:** не заменяйте его `index.html`. Создайте в корне отдельную папку, например `matematika`, загрузите туда содержимое `site` и открывайте проект по адресу `https://ваш-домен/matematika/`. Внутренние ссылки относительные, поэтому сайт будет работать и в подпапке.

## Локальный запуск

Открывать HTML двойным щелчком можно, но для проверки удобнее запустить локальный сервер.

### Windows PowerShell

Выполнять в **Windows PowerShell**, из корня распакованного проекта:

```powershell
cd site
py -m http.server 8000
```

Откройте в браузере: `http://localhost:8000`.

Остановка сервера: `Ctrl+C`.

### Windows 11 + WSL

Выполнять в **терминале WSL**. Если проект лежит, например, в `D:\KIMI\math-trainers`:

```bash
cd /mnt/d/KIMI/math-trainers/site
python3 -m http.server 8000
```

Открыть страницу из WSL в браузере Windows:

```bash
powershell.exe Start-Process "http://localhost:8000"
```

Остановка сервера: `Ctrl+C`.

## Продолжение работы в Kimi Code

1. Распакуйте проект и откройте в Kimi Code **корневую папку** `math-trainers`, а не только `site`.
2. Дайте агенту следующее задание:

```text
Прочитай AGENTS.md, CONTEXT.md, README.md, DEPLOYMENT.md и последнюю запись CHANGELOG.md.
Работай с исходниками в папке site. Сохраняй статическую архитектуру без сборки.
Перед завершением запускай tests/validate_site.py --require-node и реальные браузерные проверки.
Не ломай GitHub Actions: Pull Request только проверяется, публикуется только main после validate.
После каждой итерации обновляй CONTEXT.md и CHANGELOG.md: что изменено,
какие ответы и генераторы добавлены, какие проверки реально выполнены,
что осталось сделать. Не сообщай о проверках или публикации, которые не выполнялись.
```

3. Сформулируйте следующую задачу, например: «Добавь на страницу процентов разбор новых задач по этим фотографиям и расширь тренажёр».
4. После изменения попросите показать список изменённых файлов и результаты проверок.

## Что проверять перед повторной загрузкой на хостинг

- Запущена `tests/validate_site.py --require-node`, ошибок нет.
- Все три страницы открываются и связаны ссылками.
- На каждой странице видна обложка, видео запускается по нажатию, перематывается и не начинает играть само.
- У раскрывающихся решений видны и условие, и ответ.
- Тренажёр принимает правильный ответ, реагирует на ошибку, показывает подсказку и генерирует новое задание.
- В разделе «Мой маршрут» диагностика ведёт к нужному узлу, неверная проверка не засчитывает шаг, верная открывает следующий, а после перезагрузки прогресс восстанавливается.
- В консоли браузера нет ошибок JavaScript.
- На ширине телефона 375 px нет горизонтальной прокрутки.
- Математические ответы перепроверены независимо от генератора.

## Публикация обновления

При подключённом GitHub Pages просто отправьте изменения в `main`: публикация выполняется workflow после успешной проверки. При ручном хостинге замените изменённые HTML-файлы и загрузите новые или изменённые статические ресурсы из `site`. При первом размещении версии с видео обязательно загрузите всю папку `videos`. Markdown-документы и тесты нужны для разработки, но не публикуются как часть сайта.
