Фильтры реализованы отдельным небольшим IIFE без библиотек; скрытые разборы учебника получают атрибут `hidden` и автоматически закрываются. Задачи практики и новые разборы имеют самостоятельный класс `.practice-task`, поэтому фильтры учебника их не скрывают. Для широких таблиц используется `.table-scroll`, а для предотвращения переполнения Grid — `min-width: 0` на дочерних элементах.

Раздел «С чего начать» реализован отдельным IIFE по учебному циклу LearnHarness, без внешней модели и сетевых запросов. Ключ `localStorage` — `mathProportionsLearningRouteV1`; сохраняются результат четырёх вопросов, стартовый, текущий и завершённые шаги. Первая ошибка определяет старт; ошибки в вопросах 3 и 4 ведут в общий шаг «Как меняются величины». При четырёх верных ответах открываются задания, а уроки остаются доступны для повторения. Есть повторная проверка и полный сброс. Если браузер запрещает хранение, раздел продолжает работать и простым текстом сообщает об ограничении. На экранах от 680 px карта имеет четыре колонки, на телефоне — одну. Прокрутка после проверки ведёт к началу всего раздела с учётом закреплённого меню.

Генератор числовых пропорций строит `a : b = c : d` через `c = a × m`, `d = b × m`, затем скрывает один из четырёх членов. Текстовые шаблоны: `recipe`, `speed`, `shop`, `pipes`, `workers`. Для согласования русских форм используется `plural`.

Подсказки записаны короткими шагами без названий стран. Числовая пропорция: умножить крест-накрест и найти `x` делением; `recipe` и `shop`: сначала найти значение для одной порции или вещи, затем умножить; `speed`: сначала найти неизменную скорость, затем путь; `pipes` и `workers`: сравнить, во сколько раз изменилось число труб или рабочих, и выполнить обратное изменение времени. Все подсказки подставляют числа текущего задания и содержат проверку.

### Адаптивный маршрут LearnHarness

- Диагностика: `12 : 18 = 2 : 3`; в пропорции `4 : 6 = 10 : 15` верно `4 · 15 = 6 · 10`; на том же пути при скорости ×2 время делится на 2; бак не является обратной пропорциональностью, потому что `1 · 9 ≠ 2 · 8`.
- Проверка узла «Отношение»: `15 : 25 = 3 : 5`.
- Проверка узла «Пропорция»: `4 : 6 = 10 : x`, `x = 15`.
- Проверка узла «Зависимости»: для бака верен вывод «не обратная: `1 · 9 ≠ 2 · 8`».
- Предсказания не блокируют объяснение; итоговая проверка узла засчитывается только после верного ответа.

## CI/CD и состав полного проекта

- `.github/workflows/deploy.yml`: события `push` в `main`, `pull_request` в `main` и ручной `workflow_dispatch`. Job `validate` проверяет сайт и для не-PR упаковывает только `site`; job `deploy` запускается после `validate`, только вне Pull Request и только для `refs/heads/main`.
- Используются официальные `actions/checkout@v6`, `actions/configure-pages@v5`, `actions/upload-pages-artifact@v4`, `actions/deploy-pages@v4`. Права `contents: read`; права `pages: write` и `id-token: write` выданы только job `deploy`. Environment — `github-pages`, URL берётся из `steps.deployment.outputs.page_url`.
- `tests/validate_site.py`: Python standard library + доступный Node.js; проверяет три обязательные страницы, уникальность `id`, локальные ресурсы и якоря, безопасные `target=_blank`, отсутствие несовместимых корневых ссылок и синтаксис встроенного JavaScript. Флаг `--require-node` запрещает молча пропускать JS-проверку.
- `DEPLOYMENT.md`: команды первого push в PowerShell и WSL, выбор GitHub Actions как Pages Source, обновление через `main`, ручной запуск, безопасный `git revert`, защита среды, собственный домен и диагностика.
- `docs/GRAPHS.md`: Mermaid-графы страниц и видео, памяти тренажёров, CI/CD и зависимостей учебных тем; обновляются при изменении связей.
- `.gitignore` исключает кэши, логи, локальные настройки и ZIP; `site/.nojekyll` отключает ненужную Jekyll-обработку. Папка `.git` в пакеты не включается.
- Репозиторий создан, **Settings → Pages → Source → GitHub Actions** выбран. Первый запуск #1 остановился до настройки Pages; ручной запуск #2 успешно выполнил проверку и публикацию. Project URL: `https://shulgaop.github.io/math-trainers/` (подтверждён).
